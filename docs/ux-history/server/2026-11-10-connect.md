# Settings — connecting to the news server (2026-11-10, Android)

Tag: `ux/server/2026-11-10`

The news server (news-server-go) can read the sites, keep the articles and group the stories in place of the phone.
A phone enrolls as the journal app does: `news-server enroll-code <user>` prints a one-time code and a QR code, the app
makes a key in the Android Keystore, sends enrollDevice and keeps the client certificate. The phone's own scraping
stays as the fallback. Each option showed: not connected, connecting, connected, the code expired and the server
unreachable.

## Options
- **a — A row and a page**: one row in Settings, "שרת החדשות", with the status as its subtitle, and behind it a page
  drawn like the rest of Settings: scan first, then the address and code fields and "חיבור"; connected, a "חדשות
  מהשרת" switch and plain info rows (address, last read, stories, version, the phone and its certificate) with
  "ניתוק מהשרת" at the foot. *Picked*, promoted in 202bf44 (with a step to confirm the server's key when the code is typed).
- **b — Where the news comes from**: a הטלפון | השרת choice on top and a status card under it, grey, green or red;
  choosing השרת shows a big scan button with typing folded under it; connected, chips for stories, version and the
  device. *Not picked*.
- **c — Step by step**: three numbered steps (the command as typed on the server, scan or type, then whose code it is
  and the phone's name before anything is made), connecting ticked off stage by stage, and connected, where
  headlines, articles and stories each come from. *Not picked*.

## What they faked
- All: the whole connection. Scanning filled in 192.168.50.2:8443 and a code; connecting was a delay; one code was
  always turned down; the version, stories, certificate expiry and key protection were made up; the switch, retry
  and disconnect only changed the screen.
- serverInfo had no stories flag yet (news-server-go added `stories` after this round), and the server has no name, so
  the screens show its address.
